## Goal
Add a native menu-bar application for macOS 14 or newer on Intel and Apple Silicon, retaining the existing Windows application and schema-version-1 JSON configuration.

## Implementation Changes
1. Add consolidated Swift sources under `src/ScheduledScreenshot.Mac/` for an AppKit menu-bar host, configuration/validation/logging, scheduling/runtime persistence, and ScreenCaptureKit capture.
2. Provide one-instance ownership, explicit Screen Recording permission controls, session/sleep notifications, Capture Now, Pause/Resume, configuration editing, output/log folder access, and orderly exit.
3. Use a writable Application Support directory for settings/runtime/logs. Preserve valid settings when live edits are invalid; watch the containing directory so atomic file replacements work.
4. Support existing interval/fixed schedules, weekdays, active windows, stop conditions, filenames, JPEG/PNG and cursor settings; capture physical pixels per display and publish files without overwriting existing screenshots.
5. Add native build/package tooling for arm64, x86_64 and universal app bundles and a macOS CI workflow. Keep the offline editor shared, with platform-appropriate defaults.
6. Document macOS setup and link it from the existing overview. Keep new Markdown under `docs/`.

## Interfaces and Types
Native Swift typed settings mirror the C# schema. The main actor owns menu/config/scheduler state; capture is asynchronous and permits one batch at a time. Platform code uses AppKit, ScreenCaptureKit, ImageIO and Foundation without third-party dependencies.

## Tests
Write a repeatable native process E2E case before host implementation in `tests/cases/macos/`. Exercise configuration creation/reload/rejection, simultaneous exact deadlines, duration termination and persistence across restart, unknown-field preservation and single-instance ownership. Retain application configuration, runtime state, logs and optional captured images as the repeatable artifacts within that case. Compile both architectures, validate bundle/signature and run the existing offline editor check. The default case keeps capture paused and never requests permission. Real screen capture is an opt-in E2E path requiring the user's Screen Recording permission. Do not add unit tests after implementation or write testing results files.

## Assumptions
- macOS 14 is the minimum to use the supported single-frame ScreenCaptureKit API.
- Mac distribution is unsigned by a Developer ID; local bundles use ad-hoc signing. Public notarization needs a developer identity outside this task.
- Existing Windows source/runtime targeting remain intact.
- User authorizes useful independent delegation; core and capture workers own separate files.
